# 1. Требования к безопасности
## 1.1. Конфиденциальность данных
- Шифрование в передаче: Все коммуникации между PropDevelopment и партнерской платформой должны использовать TLS 1.3
- Шифрование хранения: Биометрические шаблоны и данные автомобильных номеров должны храниться в зашифрованном виде
- Минимизация ПДн: Передача только минимально необходимых данных (ID пользователя вместо ФИО, хэши вместо исходных данных)

## 1.2. Целостность данных
- Хеширование: Контрольные суммы для проверки целостности передаваемых данных
- Ведение журналов аудита: Запись всех транзакций с временными метками и идентификаторами

## 1.3. Доступность
- SLA соглашения: Минимум 99.9% доступности API партнера
- Резервирование: Географически распределенные узлы для отказоустойчивости
- Rate limiting: Защита от DDoS-атак через ограничение запросов

## 1.4. Защита персональных данных
- Соответствие 152-ФЗ: Регистрация обработки ПДн в Роскомнадзоре
- Анонимизация: Использование псевдонимов вместо реальных идентификаторов

# 2. Протоколы аутентификации и авторизации
## 2.1. Аутентификация системы-системы
Тип: Mutual TLS (mTLS)
Механизм:
- PropDevelopment и партнер обмениваются SSL-сертификатами
- Сертификаты подписываются доверенным УЦ или собственным корневым CA
- Верификация при каждом handshake
Преимущества: защита от MITM, сильная аутентификация

## 2.2. Аутентификация пользователей
Уровень 1: OAuth 2.0 с PKCE
- Мобильное приложение → Tenant-core-app: Authorization Code flow
- Партнерская платформа использует полученный access token

Уровень 2: JWT для передачи контекста
- В токене содержатся: user_id, permissions, session_id
- Короткое время жизни (15 минут)
- Подпись: RS256

## 2.3. Авторизация на уровне API
Модель: RBAC + ABAC
Роли:
- owner: управление своими устройствами
- admin: управление всеми устройствами дома
- system: автоматические процессы

Атрибуты:
- building_id
- apartment_id
- device_type
- time_of_day

# 3. Организация взаимодействия между системами

## 3.1. Архитектурный подход
Паттерн: API Gateway + Backend for Frontend
Компоненты:
1. API Gateway PropDevelopment (Kong/Tyk)
   - Единая точка входа
   - Rate limiting, аутентификация
2. Smart Home Integration Service (новый микросервис)
   - Преобразование форматов
   - Кеширование, ретраи
3. Partner API Gateway (сторона партнера)
   - Валидация запросов
   - Мониторинг
   
## 3.2. Протоколы взаимодействия
- Основной: REST API
- Реалтайм: WebSocket/WebRTC для видео
- События: Webhook + Message Queue (Kafka/RabbitMQ)
- Форматы данных: JSON (REST)

## 3.3. Сценарии взаимодействия
### Сценарий 1: Настройка разрешений доступа
1. Собственник → Мобильное приложение: добавляет лицо для распознавания
2. Приложение → Tenant-core-app: POST /api/v1/smart-home/permissions
3. Tenant-core-app → Smart Home Service: команда с JWT
4. Smart Home Service → Partner API
5. Partner API → Домофон: обновление базы лиц (спец. протокол)
6. Ответ идет обратной цепочкой

### Сценарий 2: Получение событий доступа
1. Домофон → Partner API: событие "лицо распознано" (спец. протокол)
2. Partner API → Webhook endpoint PropDevelopment: POST /webhooks/events
3. Smart Home Service → Message Queue: публикация события
4. Tenant-core-app подписывается на события → обновление истории
5. Tenant-core-app → Мобильное приложение: push-уведомление

### Сценарий 3: Управление в реальном времени
1. Собственник → Приложение: "открыть шлагбаум сейчас"
2. Приложение → WebSocket connection: команда управления
3. Tenant-core-app → Smart Home Service: WebSocket сообщение
4. Smart Home Service → Partner WebSocket API: команда в реальном времени
5. Partner API → Шлагбаум: команда открытия

# 4. Критические требования для аудита безопасности
- Сертификаты SSL от доверенного УЦ
- Регистрация обработки биометрических данных в Роскомнадзоре
- Аудит безопасности API партнера
- Соглашение об уровне услуг (SLA) с компенсациями
- Совместные учения по реагированию на инциденты
- Ежегодный пересмотр политик безопасности
