| Роль | Права роли | Группы пользователей |
| --- | --- | --- |
| `propdev-security-admin` (ClusterRole) | Просмотр секретов (`secrets`: get, list, watch), журналов подов (`pods/log`: get), событий кластера; чтение объектов RBAC и узлов для аудита; просмотр остальных ресурсов кластера (без create/update/delete). | Специалист по ИБ, руководитель платформенной инфраструктуры |
| `propdev-cluster-viewer` (ClusterRole) | Только чтение (`get`, `list`, `watch`) ресурсов во всех пространствах имён: поды, сервисы, deployments, ingress, configmap, PVC, events и др. **Без доступа к secrets.** | Менеджеры операционных команд, внутренние аудиторы |
| `propdev-platform-engineer` (ClusterRole) | Управление рабочими нагрузками во всех namespace: создание/изменение/удаление deployments, statefulsets, services, ingress, configmaps, PVC, HPA, jobs; просмотр namespace. **Без доступа к secrets и без изменения RBAC/узлов кластера.** | DevOps-инженеры продуктовых команд (сквозная эксплуатация Kubernetes) |
| `propdev-domain-operator` (Role, в namespace домена) | Полное управление приложениями **только в своём namespace**: deployments, services, configmaps, ingress, PVC, pods. **Без secrets и без доступа к другим доменам.** | DevOps-инженеры домена «Продажи», «ЖКУ», «Финансы», «Дата» |
| `propdev-domain-viewer` (Role, в namespace домена) | Только чтение (`get`, `list`, `watch`) ресурсов в своём namespace. **Без secrets.** | Разработчики и инженеры по эксплуатации соответствующего домена |

### Соответствие групп Kubernetes и пользователей (скрипты)

| Группа (O= в сертификате) | Пользователь | Привязка (`bind-users-roles.sh`) |
| --- | --- | --- |
| `propdev-security` | `ivan.security` | ClusterRole `propdev-security-admin` |
| `propdev-viewers` | `maria.viewer` | ClusterRole `propdev-cluster-viewer` |
| `propdev-platform` | `alex.platform` | ClusterRole `propdev-platform-engineer` |

Доменные Role (`propdev-domain-operator`, `propdev-domain-viewer`) создаются в `create-roles.sh` для namespace доменов; привязки к группам добавляются по мере появления пользователей домена.

### Пространства имён (изоляция по доменам)

| Namespace | Домен PropDevelopment |
| --- | --- |
| `propdev-sales` | Группа сервисов для продаж (витрина, CRM, онлайн-сделка и др.) |
| `propdev-hcs` | Группа сервисов ЖКУ (tenant-core, CRM собственников) |
| `propdev-finance` | Финансы (accountant-service, каталоги) |
| `propdev-data` | Дата (хранилище, BI, отчётность) |

### Порядок применения скриптов

1. `create-roles.sh` — namespace и роли  
2. `create-users.sh` — пользователи и kubeconfig  
3. `bind-users-roles.sh` — привязки и проверка `auth can-i`
